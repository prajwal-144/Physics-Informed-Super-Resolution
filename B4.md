# B4 — back-projection + fully-convolutional SISR on the fitted lens

The original DeepLense grid-based idea (Anirudh Shankar), run on this project's
corrected lens. **Six new files. Nothing existing was modified.**

| file | what it is |
|---|---|
| `backproject.py` | the source-plane back-projection `b = (Lᵀd)/(Lᵀ1)`, the coverage map (= magnification), and the bilinear source sampler that inverts it |
| `sisr_net.py` | `SourceSISR`: stem → residual blocks → long skip → PixelShuffle ×2 → softplus. **No global pooling anywhere** |
| `train_b4.py` | the self-supervision loop |
| `eval_b4.py` | scores B4 against the true source, beside the parametric fit |
| `make_figures_b4.py` | figS1–figS4 |
| `tests/test_b4.py` | five gates |

---

## Why this is worth doing

`train_pathb.py` (B2/B3) pushes the image through
`conv trunk → AdaptiveAvgPool2d(1) → 128-vector → decode a 32×32 map`.
A global average pool **discards position**, so the decoder has to reconstruct a
spatial map from a global summary. Measured consequence: the B3 correction never
exceeds 3–4% of the Sérsic, and the source-plane nmse stalls at 0.080.

B4 removes that bottleneck in two ways at once:

1. **The input is already in the source plane.** Ray-shoot the observation
   through the fitted lens and deposit each pixel at its β. The network is
   handed a picture that is already roughly the source — it only has to deblur
   and sharpen, which is exactly what SRResNet-style architectures do well.
2. **The network is fully convolutional.** A source pixel is produced by a
   receptive field centred on the corresponding input pixel. `tests/test_b4.py`
   check 5 asserts this: poke one input pixel, and the peak output response must
   land on the corresponding output pixel.

### What is the same as the original work, and what is different

| | original (`sisr.py`, `train.py` in the repo root) | B4 |
|---|---|---|
| self-supervision loop | forward-lens → PSF → downsample → MSE vs the LR image | same |
| network input | `cat([back-projection, lr_image])` | `cat([arcsinh(back-projection/σ), log₁₀(1+coverage)])` |
| architecture | SRResNet + PixelShuffle | same shape; GroupNorm instead of BatchNorm, softplus instead of ReLU |
| **lens** | **fixed SIS, one θ_E for all images, read from the manifest** | **EPL + external shear, fitted per image, unsupervised** |
| operators | precomputed sparse bank; 3 of 5 directories had forward and backward with the *same sign* | analytic in-graph deflection, validated against lenstronomy to 1e-15 |
| PSF | assumed 0.10″ Gaussian | empirical kernel, measured |
| result | source `size_ratio` **10.6–12.8** | target ≈ 1 |

Two deliberate departures, both with reasons: **GroupNorm** because Model_A arc
brightness varies 260× between images and BatchNorm would make one image's
normalisation depend on which others share its batch; **softplus** because ReLU
has exactly zero gradient on the negative side, so a pixel that starts negative
can never recover.

## The box size is a measured choice

A boxed free-form source cannot hold flux outside its box. Measured on 300 val
images:

| H (″) | n_out (×2) | out px scale | unknowns | vs ~4300 px | median flux in box |
|---|---|---|---|---|---|
| 0.8 | 32 | 0.0516″ | 1024 | 4.20:1 | 0.715 |
| 1.0 | 40 | 0.0513″ | 1600 | 2.69:1 | 0.827 |
| **1.2** | **48** | **0.0511″** | **2304** | **1.87:1** | **0.891** |
| 1.4 | 54 | 0.0528″ | 2916 | 1.47:1 | 0.935 |
| 1.6 | 62 | 0.0525″ | 3844 | 1.12:1 | 0.958 |

Default **H = 1.2**: 89% of the flux inside, 1.87:1 overdetermined, and
0.0511″/px is **2.07× finer than the detector** — inside the 3.07× median
tangential stretch that `magnification_extract.py` measures, so the resolution is
supported by the lens rather than invented.

This is the number the B2 run got wrong: it inherited H = 0.8 from a B3 default,
where **28% of the source flux is outside the box**, which is most of why its
`size_ratio` came out at 0.68.

Note the unknown-count is not the whole story here: unlike Option 2, the 2,304
values are produced by a **shared convolutional decoder conditioned on the
back-projection**, not solved for independently per image.

## What to run, in order

All from the **`Grid_Based_Experiment` root**.

### Step 0 — gates (~30 s)

```bash
python superres/tests/test_b4.py
```

Expect (these are the measured numbers):

```
1. BACK-PROJECTION ROUND TRIP
  [PASS] correlates with the true source where coverage >= 3   corr 0.998839
  [PASS] and matches its VALUE, not just its shape             median rel err 3.32%
2. COVERAGE = MAGNIFICATION
  [PASS] only in-box rays counted, each exactly once   2039 / 2039
  [PASS] coverage higher near the caustic than at the box edge   13.3 vs 1.9
3. SAMPLER ALIGNMENT     [PASS] delta reads back at its own centre  1.000000000
4. SISR SHAPE/POSITIVITY [PASS] 24 -> 48, strictly positive, finite gradients
5. SPATIAL CORRESPONDENCE[PASS] peak response lands on the poked pixel
PASS -- safe to run train_b4.py
```

**Check 1 is the one that matters.** If the back-projection does not reproduce
the source's *value* (not just its shape) to a few percent, the forward and
backward directions disagree — the exact bug that was invisible in the loss in
three of five operator directories of the original pipeline.

### Step 1 — a fitted lens for the TRAIN split (one-off)

B4 freezes the lens, so it needs one for the 6,000 training images. Two routes:

```bash
# (a) cold, ~1.4 h CPU
python superres/fit_per_image.py --root . --split train --classes axion cdm wdm \
    --n 6000 --psf-mode empirical --psf-path superres/results/psf_empirical.npy \
    --supersample 1 --out superres/results/fits_train.json

# (b) amortised, ~50 min -- and it USES the result you just proved
python superres/eval_pathb.py --ckpt superres/results/pb3_mu_best.pt --root . \
    --split train --n 6000 --out superres/results/fits_pathb_train.json \
    --out-npz superres/results/pathb_train.npz
python superres/refine_pathb.py --pathb superres/results/fits_pathb_train.json \
    --root . --n 6000 --out superres/results/fits_train.json
```

Route (b) is worth taking for its own sake: it is the amortised-initialisation
result being used for real, and it makes a nice sentence in the paper — the
speed-up is what made 6,000 training lenses affordable.

### Step 2 — a short run first (~10 min CPU)

```bash
python superres/train_b4.py --root . --classes axion cdm wdm \
    --lens-fits superres/results/fits_refined_mu.json \
    --lens-fits-train superres/results/fits_train.json \
    --n-train 600 --n-val 200 --epochs 10 --width 32 --depth 4 --lr 1e-3 \
    --out superres/results/_b4_dev.pt
```

Check the banner reads `2.07x finer than the detector` and `1.87:1`, and that
val χ² falls below ~1,500 within 10 epochs. If it does not move, stop.

### Step 3 — the real run

```bash
python superres/train_b4.py --root . --classes axion cdm wdm \
    --lens-fits superres/results/fits_refined_mu.json \
    --lens-fits-train superres/results/fits_train.json \
    --n-train 6000 --n-val 800 --epochs 40 \
    --out superres/results/b4.pt
```

~2–3 h CPU, minutes on a GPU. The checkpoint is written every epoch and
`b4_best.pt` tracks the best validation χ², so you can stop early.

**The fallback, if free-form under-performs:** add `--base sersic`. The fitted
Sérsic is then added and the network predicts only the residual, so B4 cannot do
worse than Path A — the same graceful-degradation property that makes B3 safe.

### Step 4 — score and plot

```bash
python superres/eval_b4.py --ckpt superres/results/b4_best.pt --root .
python superres/make_figures_b4.py
```

## What counts as a good result

Everything below is measured on the same 800 validation images, against the npz
`unlensed` array, PSF-matched — identical scoring to every other method here.

### The comparison table B4 has to enter

| method | corr | size_ratio | nmse | peak_ratio |
|---|---|---|---|---|
| original grid pipeline | — | **10.6–12.8** | — | — |
| Option 2, 64² linear inversion | 0.958 | 1.064 | 0.082 | — |
| B3 decoder (Sérsic + 32² correction) | 0.959 | 0.949 | 0.080 | 0.991 |
| **Sérsic, 7 params (refined Path A)** | **0.9873** | **1.081** | **0.0252** | 0.834 |

### Thresholds

| check | good | acceptable | stop and report as negative |
|---|---|---|---|
| **size_ratio** | 0.9 – 1.15 | 0.8 – 1.3 | > 2 or < 0.5 |
| source corr | ≥ 0.96 | ≥ 0.93 | < 0.90 |
| source nmse | ≤ 0.06 | ≤ 0.10 | > 0.15 |
| peak_ratio | 0.85 – 1.15 | 0.7 – 1.3 | > 1.5 |
| **flux in box** | 0.80 – 0.95 | 0.7 – 1.05 | > 1.3 (inventing flux) or < 0.6 (losing it) |
| χ²/dof, plain σ | within ~1.5× of 3228 | within 3× | > 5× |
| val/train gap | < 1.3× | < 2× | > 3× |
| centroid error | ≤ 0.8 px | ≤ 1.5 px | > 3 px |

**The single most important line is `flux in box`.** The ceiling is ~0.89 at
H = 1.2, not 1.0. Above ~1.2 the network is inventing flux — that is the failure
mode of every free-form attempt in this project so far, and `eval_b4.py` prints
it explicitly with the ceiling next to it.

### How to read the outcome, honestly

**Model_A's sources genuinely are Sérsics.** A free-form model has no prior
advantage on this data and should not be expected to beat a 7-parameter fit with
exactly the right functional form. Three outcomes, all reportable:

- **B4 lands between Option 2/B3 (nmse ≈ 0.08) and the Sérsic (0.025)** — the
  expected good result. Claim: a free-form source with no parametric assumption
  reaches within ~2× of the correct parametric model, is well posed, and is the
  deployable form for real galaxies where no Sérsic applies.
- **B4 ≈ the Sérsic** — a strong result. Say so, and check `flux in box`
  carefully before believing it.
- **B4 ≈ Option 2/B3** — the architecture did not help; the bottleneck was
  never the decoder. Report it as a measured negative, which is exactly as
  useful as the two you already have.

Do **not** claim B4 beats the parametric fit on Model_A unless the numbers say
so on all four source metrics *and* the flux-in-box histogram is centred near
0.89.

## Known risks

1. **Edge artefact.** In the 6-epoch smoke run a faint bright frame appears at
   the box boundary in figS1 — convolutional padding meeting the box edge, where
   coverage is lowest. Watch whether `--lambda-curv` and more data suppress it;
   if not, raise `--lambda-curv` to 3.
2. **Flux invention.** The smoke run gave a flux ratio of 1.36 median with a p90
   of 7.3. That is 40 images and 6 epochs and means little on its own, but it is
   the number to watch.
3. **Frozen lens.** B4 does not refit the lens, so a bad lens is a bad B4. All
   the lenses come from unsupervised fits, so this costs no validity — but it
   does mean B4 inherits the ~4% of images where the LM fit lands in the
   ellipticity–shear degeneracy. A χ² cut on the input JSON is a legitimate
   filter.
4. **Not run to convergence anywhere yet.** Everything above the thresholds
   table is either measured on the full 800-image sets (the other methods) or on
   a 40-image, 6-epoch smoke test (B4). Treat every B4 number as unverified
   until step 3 finishes.
